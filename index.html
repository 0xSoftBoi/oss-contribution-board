alloy #4162 — heartbeat receipt recheck

Pushed

alloy-rs/alloy · follow-up commit ed435145 · 2 commits

The PR really did still hang. The recheck asked the server for the chain height via eth_blockNumber — but in the failure this fixes, that call is the stale thing. If the reported height never catches up, the confirmation target is never reached and the watcher never resolves.

The regression test was written first and confirmed to fail on the original branch: watcher hung despite the transaction being confirmed: Elapsed(()). It passes after the fix. The four existing stale-RPC tests let the height catch up, which is why they missed it.

In the commit

  • Height derived from the receipts — a receipt in block n proves the chain reached n, a bound the stale server cannot contradict.
  • The eth_blockNumber request is gone entirely: one fewer RPC call per cycle.
  • Next recheck scheduled when the previous result lands, not when it is spawned.
  • The recheck task always replies, so the loop cannot stick with recheck_running set.
230 provider tests pass. The heart:: suite also dropped from 6.80s to 0.97s — it no longer waits on the stale height response.

parse_datetime #320 — the military letter j

New PR · green

uutils/parse_datetime · replaces #286, which is now closed

Every letter a–y is a military time zone and all were already in the table except j. It was missing because it is the one letter that is not a fixed offset: it means local time, so it cannot be an Offset at all.

In TZ=America/New_York: 8j → 08:00 −0400 (identical to bare 8) · 8z → 04:00 −0400 · 2026-01-01 j → −0500. It follows the DST-aware local rule zone, so it needed new builder state, not a new table entry.

Verified

  • All 26 letters a–z resolve to the same instant as GNU coreutils 9.4 — zero mismatches, in both a DST and a non-DST zone.
  • Still a zone item: 8j utc, 8 utc j, 8 j j rejected as a repeated zone.
  • 8jan still parses as a date; jj and 8foo still error.
  • 21 of 21 CI checks green, including codecov.
Chasing a codecov miss found a real defect in the new code: set_timestamp guarded every other item but not the new local-zone flag. Unreachable through today's grammar, but wrong. Fixed and covered.

mlx-lm #1361 — Gemma 4 channel thinking

Withdrawn

ml-explore/mlx-lm · rebased, then closed by you on 25 Aug

Gemma 4 has <|channel> in vocab so it trips the multi-token thinking path, but it also has <|think|> and wraps its entire response in a thought channel — so the server returns empty content. Gating on <|think|> skips detection for those models only; gpt-oss style models are unaffected.

Rebased out of conflict first, so the withdrawal was a choice rather than a surrender to drift. Closed after eleven weeks without review. The full diagnosis stays in the thread, so anyone hitting the empty-content symptom later still finds the cause.

polars #27546 — CRLF lost when transcoding CSV

603 behind

pola-rs/polars · rebased clean

When the encoding is not UTF-8, the file is read in Python text mode without newline=, so universal-newline translation rewrites the bytes before the CSV parser sees them.

Demonstrated directly: 'a,b\r\n1,"x\r\ny"' read without newline="" comes back as 'a,b\n1,"x\ny"' — a CRLF inside a quoted field silently corrupted, and the transcoded path disagreeing with the UTF-8 path on the same input.

candle #3518 — Qwen3-VL causal mask inverted

66 behind

huggingface/candle · rebased clean · cargo check passes

The mask gate is backwards: it builds the causal mask when seqlen <= 1 (single-token decode, where it is meaningless) and skips it for multi-token prefill, where it is required. The patch swaps the branches and makes the offset access panic-safe.
